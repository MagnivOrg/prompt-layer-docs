An eval file defines `evaluate(...)`, then you run:

```bash
promptlayer eval run path/to/your.eval.py
```

## Minimal example

Point `runner` at your agent entrypoint, then score tool use and the final answer:

<CodeGroup>
```python Python
from promptlayer import evaluate, contains_scorer, trajectory_scorer
from my_app.agent import run_agent  # your real entrypoint

evaluate(
    "weather-agent-eval",
    dataset=[{"input": "What is the weather in Tokyo?"}],
    runner=run_agent,
    scorers=[
        trajectory_scorer(
            accepted_scenarios=[["get_weather"]],
            mode="non_strict",
        ),
        contains_scorer(source="Output", value="72"),
    ],
    passing_score=1.0,
)
```

```javascript JavaScript
import { evaluate, containsScorer, trajectoryScorer } from "promptlayer";
import { runAgent } from "./agent.js"; // your real entrypoint

await evaluate("weather-agent-eval", {
  dataset: [{ input: "What is the weather in Tokyo?" }],
  runner: runAgent,
  scorers: [
    trajectoryScorer({
      acceptedScenarios: [["get_weather"]],
      mode: "non_strict",
    }),
    containsScorer({ source: "Output", value: "72" }),
  ],
  passingScore: 1.0,
});
```
</CodeGroup>

Python async runners use `aevaluate`. JavaScript uses async `evaluate`. Full harness setups (OpenAI Agents, Claude, LangChain, and more) are in the [Quickstart](/sdks/evals/quickstart).

## Dataset

Cases feed the runner and scorers. [Datasets](/sdks/evals/datasets) covers inline cases and dashboard Tables:

- `input` — required; passed to the `runner`
- `expected` — optional; expected **output** (Contains, Compare, …)
- `expected_trace` / `expectedTrace` — optional; only for [Trajectory](/sdks/evals/scorers/overview#trajectory). This is Trajectory config (which tools should run), not the answer text

## Runner

The `runner` is any callable that takes an `input` and returns a final value (not a stream). There is no framework allowlist.

For Trajectory, tools must appear as `Tool: <name>` spans on the imported Trace — use a framework helper or `traceTool`. That contract is on [Runner](/sdks/evals/agent-tracing).

## Scorers and columns

- **Scorers** become scorecard steps on the experiment sheet. Declare them with [Scorers](/sdks/evals/scorers/overview). Rollup matches [Scorecards](/features/tables/scorecards); check types match [Column Types](/features/tables/column-types).
- **Columns** are optional processing steps before scorers. Declare them with [Columns](/sdks/evals/columns/overview); types match [Column Types](/features/tables/column-types).

## Other `evaluate(...)` options

| Goal | Python | JavaScript |
| --- | --- | --- |
| Cases | `dataset` | `dataset` |
| Agent under test | `runner` | `runner` |
| Scorecard checks | `scorers` | `scorers` |
| Processing columns | `columns` | `columns` |
| Fail below a bar | `passing_score` | `passingScore` |
| Run cases in parallel | `max_concurrency` | `maxConcurrency` |
| Print failing rows | `include_failure_examples` | `includeFailureExamples` |
| Reuse a Table | `table_id` | `tableId` |
| Folder for a new Table | `folder_id` | `folderId` |
| Experiment sheet name | `experiment_name` | `experimentName` |
| Auth (prefer env for CLI) | `api_key`, `base_url` | `apiKey`, `baseURL` |

Do **not** pass top-level `sheet_id` / `sheetId`. Use `dataset.sheet_id` / `dataset.sheetId` only when the dataset comes from a dashboard sheet.

## What you get back

On success, the SDK creates (or reuses) a Table, writes a dedicated experiment sheet, configures your scorecard, and returns an `EvalResult` with a dashboard URL. For failure handling and `passing_score`, see [Results and failures](/sdks/evals/results-and-failures).
